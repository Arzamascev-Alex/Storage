# Storage

Проектная работа на C# / .NET 10: 
TCP-сервер для хранения объектов UserProfile в памяти с доступом по строковому ключу.

Проект развивается в рамках курса: парсинг команд, асинхронная работа с TCP, потокобезопасность, сериализация, нагрузочное тестирование и наблюдаемость.

## Структура решения

1. Storage.Core - хранилище, модель UserProfile и парсер команд.
2. Storage.Server - TCP-сервер, ограничения и телеметрия.
3. Storage.Tests - автоматические тесты.
4. Storage.LoadTests - TCP-клиент и нагрузочные сценарии.
5. Storage.Benchmarks - бенчмарки сериализации.
6. Storage.Generators - генератор кода бинарной сериализации.

```
## Протокол

Команды передаются в UTF-8.
Каждая команда заканчивается `\n` или `\r\n`.

| Команда 				| Назначение 								| Ответ 			|

| SET key <JSON> 		| Сохранить UserProfile по ключу 			| OK 				|
| GET key 				| Получить объект по ключу 					| JSON или (nil) 	|
| DELETE key 			| Удаление 									| OK 				|

JSON для SET должен соответствовать модели UserProfile и передаваться
в одной строке. Неверные команды или некорректный JSON возвращают ERROR.

Сервер поддерживает несколько команд в одном чтении из сокета
и накопление команды, поступающей частями.

Данные хранятся в памяти и теряются при перезапуске сервера.

## Пример запроса через PowerShell

$client = [System.Net.Sockets.TcpClient]::new()
$client.Connect("127.0.0.1", 8080)

$stream = $client.GetStream()
$stream.ReadTimeout = 3000
$reader = [System.IO.StreamReader]::new($stream)

try {
    $bytes = [System.Text.Encoding]::UTF8.GetBytes("GET test`r`n")
    $stream.Write($bytes, 0, $bytes.Length)

    $reader.ReadLine()
}
finally {
    $reader.Dispose()
    $client.Dispose()
}
```

Если ключ отсутствует, сервер возвращает `(nil)`.

## Ограничения

- Максимальный размер сообщения 4096 байт, включая перевод строки.
- Если буфер заполнен, а завершающий `\n` не получен,
  сервер закрывает соединение без выполнения команды.
- Одновременно обслуживается не более 100 клиентов.
- Ограничение клиентов реализовано через SemaphoreSlim.
- Место освобождается в finally при завершении обработки клиента.

Лимит сообщений ограничивает входящий буфер, но не общий объём
данных, сохранённых в хранилище.

## Наблюдаемость

Используется OpenTelemetry с экспортом в консоль.

Для каждой обрабатываемой команды создаётся Activity `storage.command`
с тегами:

- command.name — имя команды.
- command.size — размер команды в байтах без перевода строки.

Метрики:

- storage.commands.processed — количество обработанных команд.
- storage.command.duration — длительность обработки в миллисекундах.

Время измеряется вокруг ExecuteCommand, без ожидания входящих данных
и отправки ответа клиенту.

Счётчик учитывает завершившиеся вызовы ExecuteCommand, включая
возврат ERROR или (nil). Вызовы, завершившиеся исключением,
в эти метрики не попадают.

Метрики выводятся периодически, трассировки — после завершения операций.
